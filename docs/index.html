A trading system run by independent agents

Nine small services each do one job (read market data, analyse news, pick trades, review them with an AI agent, execute and report) and pass messages to each other through a queue. It paper-trades Indian stocks (NSE) with fake money. This page walks through how it works, using results from the real system.

    2 · The AI reviewer: an agent that gathers evidence

    Before a buy goes through, an AI agent (Claude) gets a second look. It doesn't just answer from the prompt: it decides which tools to call (current holdings, recent news, price history), reads the results, then approves or rejects. Pick a scenario and step through it.

    Illustrative example. The format matches the real agent; the stock and values are made up.

    Why it's built this way

    • Tools, not a giant prompt. The agent fetches only the evidence it needs, usually 2–4 calls.
    • No peeking at the future. Every tool only returns data from before the trade's timestamp, so replaying old dates is a fair test.
    • It can't break trading. It runs alongside the trader. If the AI is down or over budget, the trade isn't blocked and the outage is logged, never mistaken for a "reject".
    • Hard cost limits. A daily review cap and a monthly dollar cap shared by every AI call.
    • Scored against reality. An evaluation script checks each verdict against what the stock actually did next: were the rejects really losers?

    5 · Built to survive failures

    Things go wrong: networks drop, laptops sleep, messages get delivered twice. The system is designed so none of that causes a wrong trade.

    A message delivered twice

    Queues may re-send a message after a crash. Each trade signal has a fixed ID, so a repeat is ignored.

    Crash and restart

    Every service keeps its state in the database, not in memory. Kill it at any moment and on restart it re-reads unfinished messages and catches up. A watchdog restarts a service whose scheduler froze after the machine slept.
